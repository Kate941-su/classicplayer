# CMSL Classical Player — 製品・技術仕様書

- 版: 1.0（2026-11-20）
- 対象: iOS / Android ネイティブアプリ、カタログ生成パイプライン
- 読者: 実装担当（Claude Code）、オーナー

---

## 1. 概要

### 1.1 コンセプト
**「広告なしで、クラシックだけを、静かに聴ける」** 専用プレイヤー。
音源は「CMSL クラシック名曲サウンドライブラリー」（https://classical-sound.seesaa.net/ 、制作: ANDO TOWA）がフリー素材として公開している mp3 を利用する。アプリはカタログを整理して見せ、mp3 を直接ストリーミング再生する。

### 1.2 基本方針（破ってはいけない原則）
1. **クラシック専用**。CMSL 内の J-POP・洋楽（「ラストシンフォニー」系）カテゴリは収録しない。
2. **広告なし・トラッキングなし**。広告 SDK、解析 SDK、クラッシュ収集 SDK を入れない（ストアのプライバシー表示を「データ収集なし」にする）。
3. **アカウント不要**。ログイン機能なし。お気に入り等は端末内保存のみ。
4. **音楽は全曲無料**。課金で再生や曲を制限しない。マネタイズは任意の寄付（チップ）だけ（§9）。
5. **クレジットを必ず表示**。CMSL のクレジットを「この曲について」画面と「情報」画面に表示する。
6. **サーバーに負担をかけない**。CMSL のサイトを、アプリから直接スクレイピングしない。カタログは事前生成した静的 JSON を配信し、アプリは mp3 の再生時だけ音源のサーバーにアクセスする。音源のサーバーは CMSL（`classical-sound.up.seesaa.net`、https）と、2011〜2012 年ごろの記事の mp3 を置いている制作者の旧サーバー 3 つ（`classical-music.aki.gs`、`andotowa.sakura.ne.jp`、`classical-music.sakura.ne.jp`）に限る。旧サーバーは https に対応していない（403 か接続不可。2026-11-21 確認）ため、**この 3 つに限り平文の http を許可する**（Android は `network_security_config.xml`、iOS は ATS の例外。ほかのホストは https のみ）。

### 1.3 音源の利用条件（CMSL サイトの記載に基づく）
- ダウンロード用 mp3（「🎵こちら」ボタンなど `.mp3` リンク）はフリー素材。商用利用・加工が可能で、使用許諾も連絡も不要。
- 著作権は制作者に帰属する（放棄されていない）。表示ライセンスは Creative Commons 表示 2.1 日本。
- 制作者の旧サーバー（§1.2）に置かれた、古い記事のダウンロード用 mp3 も同じ条件で扱う（オーナーが 2026-11-21 に確認。サイトの記載でフリー素材・連絡不要）。
- **ストリーミング専用のファイルはライセンス対象外**なので収録しない。
- 再配布の可否は明記されていない。アプリはファイルを再ホストせず、CMSL の URL から直接再生する。
- ストア審査に備えて、運営者から**書面（メール）で許諾を得る**（§10.2）。

## 2. システム構成

```
┌────────────────────────┐   月1回 + 手動実行
│ GitHub Actions          │──────────────┐
│  catalog/build_catalog  │  巡回 (1.5s間隔) ▼
└──────────┬─────────────┘   classical-sound.seesaa.net（HTML）
           │ catalog.json / manifest.json を生成・検証
           ▼
┌────────────────────────┐
│ 静的ホスティング          │  GitHub Pages（または Cloudflare Pages）
│  /v1/manifest.json      │
│  /v1/catalog.json       │
└──────────┬─────────────┘
           │ HTTPS GET（ETag / If-None-Match）
           ▼
┌────────────────┐  ┌────────────────┐
│ iOS アプリ       │  │ Android アプリ  │  ── 再生時のみ ──▶ classical-sound.up.seesaa.net/*.mp3（と旧サーバー 3 つ。§1.2）
│ SwiftUI+AVPlayer│  │ Compose+Media3 │
└────────────────┘  └────────────────┘
```

- 配信先は **GitHub Pages**（`https://kate941-su.github.io/classicplayer/v1/`）に決定（2026-11-20、オーナー）。アプリはこのベース URL を定数で持つ。
- サーバー側のロジックは持たない（静的ファイルのみ）。検索・絞り込みはすべてアプリ内で行う。
- アプリには**同梱カタログ（シード）**を入れる。初回起動やオフライン時もカタログを閲覧できる。

## 3. カタログ

### 3.1 生成パイプライン（`catalog/`）
- `build_catalog.py`（既存）: サイトを巡回し、`catalog.json` と `catalog.report.json` を出力する。
- 追加実装:
  - `overrides.json`: 手動補正ファイル。タイトル解析の失敗、ジャンル名の整形、作曲家名の統一、除外する記事を記述する（§3.4）。
  - `genre_map.json`: CMSL のカテゴリ名をアプリの表示ジャンルに対応づける（§3.3）。
  - `validate_catalog.py`: `schema/catalog.schema.json` で検証し、整合性をチェックする（ID 重複、参照切れ、URL 形式）。
  - `make_manifest.py`: `manifest.json` を生成する（バージョン、SHA-256、件数、生成日時）。
- 実行: **オーナーの手元**で月 1 回、`tool/update-catalog.sh` を実行する（オーナーの決定、2026-11-21）。巡回（間隔 1.5 秒。HTML キャッシュ `catalog/cache/` を使い、2 回目以降は差分取得）→ 検証 → `manifest.json` 作成 → `site/v1/` に出力し、PR でコミットする。main にマージすると `pages.yml` が GitHub Pages に公開する。手順は `docs/catalog-pipeline.md`
- GitHub Actions からは巡回しない。2026-11-21 に試したところ、robots.txt の判定で全面禁止となり 1 ページも取得できなかった（手元からは許可されている）。巡回側の判定は回避しない
- 安全弁: 前回（`site/v1/manifest.json` と公開中の manifest）より曲数が 10% 以上減ったら、スクリプトは出力せず、PR の CI も失敗する（サイト構造の変化を検知するため）。`site/v1/` の検証と manifest の一致は PR と公開の直前に CI で確かめる

### 3.2 スキーマ（schemaVersion 2）
正式な定義は `schema/catalog.schema.json`。要点:

```jsonc
{
  "schemaVersion": 2,
  "generatedAt": "2026-12-01T03:00:00+00:00",
  "source": "https://classical-sound.seesaa.net/",
  "license": { "name": "...", "credit": "CMSL クラシック名曲サウンドライブラリー", "url": "...", "notes": "..." },
  "genres":    [{ "id": "piano", "name": "ピアノ", "nameEn": "Piano", "order": 10, "trackCount": 120 }],
  "composers": [{ "id": "l-v-beethoven", "name": "ベートーヴェン", "nameEn": "L.V.Beethoven", "trackCount": 42 }],
  "works":     [{ "id": "l-v-beethoven--...", "title": "ピアノソナタ 第8番 ハ短調 Op.13 「悲愴」", "composerId": "...", "genreId": "..." }],
  "tracks": [{
    "id": "474143449",                 // 記事ID（1記事に複数mp3があれば "474143449-0" 形式）。恒久的に変えない
    "title": "ベートーヴェン：ピアノソナタ 第8番 ... 第2楽章 [2020][AR]",
    "titleEn": "L.V.Beethoven:Piano Sonata No.8 ...",
    "composerId": "l-v-beethoven",
    "workId": "l-v-beethoven--...",
    "genreId": "piano",
    "movement": "第2楽章",             // null可
    "tags": ["2020", "AR"],
    "audioUrl": "https://classical-sound.up.seesaa.net/image/....mp3",
    "fileName": "....mp3",
    "articleUrl": "https://classical-sound.seesaa.net/article/474143449.html",
    "publishedAt": "2020-03-20T18:18:00+09:00",   // null可
    "durationSec": null                             // 将来拡張。現状は null
  }],
  "replacedTracks": { "427916377": "500111088-0" }  // 新しい録音に置き換えて外した曲 → 置き換え先（下の「作品と録音」）
}
```

**契約のルール**（`schema/catalog.schema.json` で検査する）:
- 生成側はスキーマにあるキーを**すべて出力**する（値がないときは省略せず `null`。`tags` は空配列）。スキーマにないキーは出力しない（`additionalProperties: false`）。
- アプリのデコーダーは**未知のキーを無視**する（任意フィールドの追加は `schemaVersion` を上げずに行えるようにするため）。
- URL は `audioUrl` が `https://classical-sound.up.seesaa.net/〜.mp3` か、旧サーバー 3 つの `http://〜.mp3`（§1.2）、`articleUrl` が `https://classical-sound.seesaa.net/article/{数字}.html` に限る。日時は RFC 3339（タイムゾーン付き）。
- ID の重複と参照切れ（`composerId` / `workId` / `genreId`）はスキーマでは表せないので、`validate_catalog.py` で検査する（PLAN 0.5）。

**ID の安定性**: `track.id` はお気に入りや再生履歴のキーになるため、生成し直しても変えてはならない。記事ID（Seesaa の `/article/{id}.html`）を元にする。`composer.id` と `work.id` は slug なので、表記揺れの修正で変わることがある。アプリはこれらを永続化しない（永続化するのは `track.id` だけ）。

**作品と録音**（PLAN 0.6 で決定。2026-11-21 の全件巡回とオーナーの判断をもとに）:
- CMSL には同じ曲の別録音が多い（例: 「運命」に 2006・2014・2015・2018・2019 AR・2020 IR・2023 の録音）。**同じ作品の別録音は、新しい録音だけを残す**（オーナーの決定、2026-11-21）。作品は「作曲家 + 作品名」でまとめ、作品名に録音は書き添えない。作品名の空白・記号・括弧の種類（「」《》『』）・全角半角の違いと、作品番号の書き方（`作品64`・`Op64`・`Op.64`、`D.821`・`D821`）の違いは同じ作品として扱う。愛称のない作品名（`交響曲第9番 ニ短調 作品125`）は、愛称を除くと同じになる愛称つきの作品名が 1 つだけあれば同じ作品にする（愛称が違う `「夏」`・`「冬」` は別の作品）。作品の ID と作品名は、最も新しい録音の曲の表記を使う。誤記（`ペアレス`・`ニュルンベルグ` など）は `overrides.json` で直す
- 新しさは**楽章ごと**に比べる。同じ作品・同じ楽章（楽章のない曲は作品全体）に、より新しい録音の曲が別の記事にあれば、古い曲を外す。新しい録音にない楽章は古い録音のまま残す（作品の中で録音が混ざることがある）。複数の楽章を 1 ファイルにした曲（`第3-4楽章`）は、その楽章がすべて新しい録音にあるときだけ外す
- 録音の新しさは、録音年（記事のタグ `[2019][AR]` かファイル名 `…-2019-AR.mp3`。なければ記事の公開年）→ 記事の公開日時の順で比べる。1 記事の mp3 は同じ録音として扱い、互いに置き換えない（ピアノ版と管弦楽版、カラオケ版など）
- 外した曲は `replacedTracks`（外した曲 ID → 同じ楽章の新しい録音の曲 ID。値は必ず `tracks` にある）に載せ、`catalog.report.json` の `supersededRecordings` にも載せる。アプリはお気に入り・履歴・保存したキューの ID を読み替える（§6）。CMSL に古い記事が残っている限り、毎回の生成で同じ対応が出る
- 作品の曲は楽章番号順に並べる（アプリも楽章番号順に表示する。§4.5）
- **まとめ記事**（「オンライン特別プログラム」や、ファイル名の作曲家が 2 人以上いる記事）は、曲ごとにファイル名（`作曲家-作品-楽章-年-種別.mp3`）から作曲家・作品・楽章を決め、作曲家・作品名・ジャンルは通常の記事の同じ曲に合わせる。トラックのタイトルは `作曲家：作品 楽章[年][種別]` の形で作る
- 1 記事に mp3 が複数あり、ファイル名に楽章（`1st`・`2nd`…）があれば、曲ごとの楽章にする（記事タイトルの「第1,2楽章」を分ける）
- 同じ mp3 を再掲した記事（紹介記事・再投稿）は、最初に公開された記事の曲だけ残し、`catalog.report.json` の `duplicateAudio` に載せる
- 外したくない録音（リハーサル録音が完成版を置き換える場合など）は、`overrides.json` の `exclude` で新しい方の記事を外す。2026-11-21 時点: 第九 第1楽章のリハーサル録音（記事 503525038）を外している（オーナーの指示）
- 2026-11-21 の全件巡回: 旧サーバーの曲を含めて 739 曲 → 除外 1 曲・重複 4 曲・置き換え 214 曲を除いて **520 曲**（作曲家 118、作品 427）

### 3.3 ジャンル
CMSL のカテゴリをそのまま使うと、名前が長いものや細かすぎるものが出る。`genre_map.json` で次の表示ジャンルにまとめる（PLAN 0.6 で、実際のカテゴリ 14 種をもとに確定）。

| 表示ジャンル | nameEn | 例（CMSL カテゴリ） |
|---|---|---|
| 交響曲 | Symphonies | 交響曲 |
| 管弦楽曲 | Orchestral | 管弦楽曲、バレエ音楽、弦楽合奏曲、吹奏楽曲 |
| 協奏曲 | Concertos | 協奏曲 |
| ピアノ | Piano | 器楽曲・Piano |
| 器楽・室内楽 | Chamber & Instrumental | 室内楽曲、器楽曲、器楽曲・Guitar |
| 声楽・オペラ | Vocal & Opera | 歌劇、声楽曲 |
| バロック | Baroque | （2026-11-21 時点で該当するカテゴリはない。曲のないジャンルは出力しない） |
| その他 | Other | 国歌・賛美歌・民謡、映画音楽・ミュージカル・ポピュラー |

`order` で表示順を指定する。マップにないカテゴリは「その他」に入れ、`catalog.report.json` の警告に載せる。

### 3.4 overrides.json
```jsonc
{
  "exclude": ["500000002"],                       // 記事IDで除外
  "tracks": {                                      // 記事ID、またはまとめ記事の曲 ID（記事ID-連番）ごとの上書き
    "474143449": { "composer": "ベートーヴェン", "work": "...", "movement": "第2楽章" },
    "476991508-6": { "work": "花の歌 Op.39", "genre": "piano" }
  },
  "composerAliases": { "L.v.ベートーヴェン": "ベートーヴェン", "ベートーベン": "ベートーヴェン", "Lange": "ランゲ" },  // まとめ記事のファイル名の先頭の語にも使う
  "composerEn": { "ベートーヴェン": "Ludwig van Beethoven" }
}
```

### 3.5 manifest.json
```json
{ "schemaVersion": 2, "catalogVersion": "2026.12.01", "catalogUrl": "catalog.json",
  "sha256": "…", "trackCount": 812, "generatedAt": "…", "minAppSchema": 2 }
```
正式な定義は `schema/manifest.schema.json`。`sha256` は catalog.json のバイト列のハッシュ。`catalogVersion` は `generatedAt`（UTC）の日付で、中身（sha256）が前回と同じなら前回の値を引き継ぎ、同じ日に出し直すときは `YYYY.MM.DD.2` のように連番を付ける（`make_manifest.py`）。
アプリは manifest を先に取得し、`catalogVersion` が変わったときだけ catalog を取得する。`schemaVersion` がアプリの対応範囲外なら、更新せず手持ちのカタログを使い続ける。

## 4. 画面仕様

### 4.1 画面構成
```
タブ: [ホーム] [検索] [ライブラリ] [情報]
                 └ 下部にミニプレイヤーを常時表示（再生中のみ）→ タップでフルプレイヤー
ホーム ─ ジャンル一覧 ─ ジャンル詳細（作曲家一覧）─ 作曲家詳細（作品一覧）─ 作品詳細（楽章・トラック一覧）
```

### 4.2 ホーム
- 上部: 「新着」横スクロール（`publishedAt` が新しい順に10件）。
- 本体: ジャンルのカードグリッド（2列。名前と曲数を表示）。並びは `order` 順。
- 「おまかせ再生」ボタン: 全曲（または選択中のジャンル）からシャッフル再生する。

### 4.3 ジャンル詳細
- 作曲家の一覧（曲数の多い順。「名前順」に切り替え可能）。
- 右上に「このジャンルをシャッフル再生」ボタン。

### 4.4 作曲家詳細
- 作品の一覧（各作品の楽章数を表示）。作品が1つで1トラックだけのものは、トラック行として直接表示する。
- 「すべて再生」ボタン（作品順、楽章順）。

### 4.5 作品詳細
- トラック（楽章）の一覧。並びは楽章番号順（`movement` の数値を抽出。なければ `publishedAt`）。
- 行: 楽章名、タグ（例「2020」「AR」）、お気に入りの☆。
- 「作品を通して再生」ボタン。1行をタップすると、その曲から作品の最後までをキューに入れる。
- 行の「…」メニュー: お気に入り、次に再生、キューに追加、ダウンロード（§5.1。済みなら「ダウンロードを削除」）、この曲について（原典記事へのリンクとクレジット）。
- 「作品をダウンロード」ボタン（§5.1）。ダウンロード済みの曲の行には印を付ける。

### 4.6 検索
- 対象: 曲タイトル（日本語・英語）、作曲家名（日本語・英語）、作品名。端末内のカタログだけを検索する（ネットワーク不要）。
- 正規化: 全角と半角、ひらがなとカタカナ、長音・中黒・空白、大文字と小文字、「ヴ/ブ」「ヴェ/ベ」の揺れを吸収する（例「ベートーベン」→ベートーヴェン、「beethoven」）。
- 結果は「作曲家」「作品」「曲」のセクションに分けて表示する。入力のたびにインクリメンタルに更新する（150ms のデバウンス）。
- 未入力時は「最近の検索」（端末内に最大10件）とジャンルのチップを表示する。

### 4.7 ライブラリ
- お気に入り（曲）。並び替えは追加日順、作曲家順。
- 最近再生した曲（最大100件）。
- ダウンロード（§5.1）: ダウンロードした曲の一覧（作曲家順）、合計サイズ、削除（1 曲ずつ・すべて）、ダウンロード中の進み具合。
- ※ プレイリスト機能は v1.1 以降（§11）。

### 4.8 フルプレイヤー
- 表示: 作品名、楽章、作曲家、ジャンルの色に合わせた生成アートワーク（§4.10）。
- 操作: 再生/一時停止、前/次、シークバー（経過時間と残り時間）、シャッフル、リピート（オフ/全体/1曲）、お気に入り、キュー表示、共有（原典記事の URL）、スリープタイマー（§5.2）。
- 「この曲について」: 原典記事へのリンクとクレジットを表示する。

### 4.9 情報
- アプリについて、**CMSL クレジット（ロゴではなくテキストとリンク）**、利用条件の要約、プライバシーポリシー（「データを収集しません」）、オープンソースライセンス一覧、お問い合わせ、カタログの版と更新日、手動更新ボタン。
- 「開発を応援する」（寄付。§9）。

### 4.10 アートワーク
CMSL の音源には画像がないため、**アプリ内で生成する抽象アートワーク**を使う。作曲家 ID のハッシュから色相を決め、ジャンルごとに図形パターンを変える（例: ピアノは鍵盤の縞、交響曲は同心円）。外部の画像や肖像写真は使わない。

### 4.11 デザイン
- トーンは落ち着いた「コンサートホール」。ライトとダークに対応（システム設定に従う）。
- 日本語を主とし、英語ローカライズも用意する（端末の言語設定に従う）。英語 UI では `nameEn` / `titleEn` を優先して表示し、ない場合は日本語にフォールバックする。
  - 作品画面の行などに出す短い曲名（英語）: `titleEn` の作曲家の区切り（最初の `:` か `：`）より後ろから、最初の楽章の印（ローマ数字か数字の直後に `.` か `:` と空白。前は空白かコロン）以降を使う。例: `…"pathetique"：II. Adagio cantabile` → `II. Adagio cantabile`、`…"From the New World" I: Adagio - Allegro molto` → `I: Adagio - Allegro molto`。印がなく楽章もない単曲は区切りより後ろ（`Recuerdos de la Alhambra`）。それ以外は日本語の `movement`
  - ホームの「新着」など、楽章名だけでは曲が分からない所には作品名を出す（下に「作曲家 · 楽章」）。英語は `titleEn` の区切りより後ろから楽章の印の前まで（`Piano Sonata No.14 in C sharp minor, Op.27-2 "Moonlight"`）、なければ作品の `title`
- アクセシビリティ: Dynamic Type / フォントスケールに対応。VoiceOver / TalkBack 用のラベルを付ける。タップ領域は 44pt / 48dp 以上。コントラストは WCAG AA。

## 5. 再生仕様

| 項目 | 仕様 |
|---|---|
| 方式 | `audioUrl` を HTTPS で直接ストリーミングする（プログレッシブ再生） |
| バックグラウンド再生 | 対応（iOS: Audio Background Mode / Android: MediaSessionService） |
| ロック画面・通知 | タイトル、作曲家、アートワーク、再生/一時停止、前/次、シーク |
| 割り込み | 電話やほかのアプリの再生で一時停止し、割り込みが終わったら再開する（OS の推奨に従う） |
| イヤホンを外したとき | 一時停止する |
| ギャップレス | 同じ作品の連続した楽章は、次の曲を先読みして途切れを最小にする（iOS: AVQueuePlayer / Android: Media3 のプレイリスト） |
| キュー | 「作品を通して」「ジャンルのシャッフル」「お気に入り」などのコンテキストからキューを作る。並べ替えと削除ができる |
| 状態の復元 | アプリを再起動したら、最後のキューと位置を復元する（自動では再生しない） |
| エラー | 404 やネットワークエラーの曲はスキップし、トーストで知らせる。3曲続けて失敗したら停止する |
| キャッシュ | OS / プレイヤー標準の HTTP キャッシュ（最大 200MB）。オフラインで聴くためのダウンロードは §5.1 |
| ダウンロード済みの曲 | 端末のファイルから再生する（ネットワーク不要。§5.1） |
| 音量 | 端末の音量に従う。アプリ独自のノーマライズはしない（「夜間・小音量」スイッチは v1.1。§11） |

### 5.1 ダウンロード（オフライン再生）
オーナーの決定（2026-11-21）で v1.0 に入れる（もとは「許諾を得てから v1.1 で検討」としていた）。
- 曲ごと（曲の「…」メニュー）と作品ごと（作品画面の「作品をダウンロード」）にダウンロードできる。ダウンロード済みの曲は、行に印を付け、再生時は端末のファイルを使う
- 取得元はカタログの `audioUrl` だけ（§1.2。旧サーバーの http も同じ例外の範囲）。**1 曲ずつ順番に**取得し、同時に複数は取らない（音源のサーバーに負担をかけない。§1.2-6）
- 「Wi-Fi のときだけダウンロード」の設定（既定はオン。モバイル通信・省データモードでは待つ）
- 失敗した曲は未ダウンロードに戻す（自動では再試行しない。もう一度選べば取り直す）。取得中のファイルは一時ファイルに書き、完了してから置く
- 保存したファイルはアプリの外に出さない（共有・書き出しの機能は作らない）。端末内に一時的に保存するだけで、再配布はしない
- カタログを更新して、曲が新しい録音に置き換わった（`replacedTracks`）ときと、カタログから消えたときは、その曲のファイルを消す（新しい録音は自動ではダウンロードしない）
- 永続化する ID は `track.id` だけ（ファイル名に使う）
- ライブラリの「ダウンロード」で、一覧・合計サイズ・削除（1 曲ずつ・すべて）
- プライバシーポリシー（`site/privacy/`）の「端末の中だけに保存するデータ」に、ダウンロードした音源を追加する。データの収集はない
- TODO(owner): CMSL への連絡（PLAN 0.10）で、オフライン再生のための端末内の保存も伝える。App Store の審査で指摘されたら、審査メモ（§10.2）にダウンロード用 mp3 のライセンス（フリー素材）を書いて説明する

### 5.2 スリープタイマー
- フルプレイヤーの月のボタンから選ぶ: 15・30・45・60・90 分、「この曲の終わりまで」、オフ
- 時間になったら、約 10 秒かけて音量を下げてから一時停止し、音量を元に戻す（「この曲の終わりまで」は曲が終わったところで止め、次の曲に進まない）
- 設定中はボタンに残り時間を出す。再生を一時停止していても時間は進む。時間になったときに止まっていれば何もしない
- タイマーは保存しない（アプリを終了すると消える）

## 6. データ保存（端末内）

| データ | iOS | Android |
|---|---|---|
| カタログ（最新版） | Application Support/catalog.json | filesDir/catalog.json |
| 同梱シード | Bundle resource | assets/catalog.json |
| お気に入り（track.id と追加日時） | SwiftData | Room |
| 再生履歴（track.id と日時、最大100件） | SwiftData | Room |
| 最近の検索 | UserDefaults | DataStore |
| 再生キューと位置 | UserDefaults（JSON） | DataStore |
| ダウンロードした音源（§5.1） | Application Support/Downloads/{track.id}.mp3（バックアップの対象外） | filesDir/downloads/{track.id}.mp3 |
| ダウンロードの設定（Wi-Fi のときだけ） | UserDefaults | DataStore |

カタログを読み込むたびに、お気に入りと再生履歴の `track.id` のうち `replacedTracks` にあるものを置き換え先に書き換える（追加日・再生日時はそのまま。置き換え先がすでにあれば古い方を消す）。保存したキューは再生時に読み替える。
カタログを更新して `track.id` が消え、`replacedTracks` にもない場合、そのお気に入りは「この曲は現在利用できません」としてグレー表示する（削除はしない）。

## 7. カタログ取得と更新

1. 起動時、ローカルカタログ（なければシード）を即座に読み込んで表示する。ネットワークの完了を待たない。
2. バックグラウンドで `manifest.json` を取得する（ETag を使用。前回の確認から24時間以内ならスキップ）。
3. `catalogVersion` が新しければ `catalog.json` を取得し、SHA-256 とスキーマを検証してから差し替える。失敗したら旧版を維持する。
4. 「情報」画面の手動更新ボタンでは、24時間の制限を無視して確認する。

## 9. マネタイズ（寄付・チップ）

- 形式: **消耗型のアプリ内課金による「チップ」**を3段階（例 ¥160 / ¥480 / ¥1,200。価格帯は各ストアのティアから選ぶ）。
- 何もアンロックしない（純粋な応援）。購入後に「ありがとうございます」画面を表示し、端末内に「応援者」バッジのフラグを立てる（表示のみで、機能差はない）。
- 外部の寄付リンク（Ko-fi、PayPal など）は**アプリ内に置かない**（ストアの規約違反になるため）。
- 「復元」は不要（消耗型のため）。ただし応援者バッジは端末内のフラグなので、再インストールで消える旨を表示する。
- 寄付を促す表示は「情報」タブと、累計再生が50曲に達したときの1回だけの控えめなカード。**再生の途中や起動時にポップアップは出さない**。
- CMSL への還元方針（収益の一部を還元するか、などの扱い）は、オーナーが運営者と相談して決める。決まったら、寄付画面の説明文に反映する。
