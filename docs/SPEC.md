# CMSL Classical Player — 製品・技術仕様書

- 版: 1.0（2026-11-20）
- 対象: iOS / Android ネイティブアプリ、カタログ生成パイプライン
- 読者: 実装担当（Claude Code）、オーナー

---

## 1. 概要

### 1.1 コンセプト
**「広告なしで、クラシックだけを、静かに聴ける」** 専用プレイヤー。
音源は「CMSL クラシック名曲サウンドライブラリー」（https://classical-sound.seesaa.net/ 、制作: ANDO TOWA）がフリー素材として公開している mp3 を利用する。アプリはカタログを整理して見せ、mp3 を直接ストリーミング再生する。

### 1.2 基本方針（破ってはいけない原則）
1. **クラシック専用**。CMSL 内の J-POP・洋楽（「ラストシンフォニー」系）カテゴリは収録しない。
2. **広告なし・トラッキングなし**。広告 SDK、解析 SDK、クラッシュ収集 SDK を入れない（ストアのプライバシー表示を「データ収集なし」にする）。
3. **アカウント不要**。ログイン機能なし。お気に入り等は端末内保存のみ。
4. **音楽は全曲無料**。課金で再生や曲を制限しない。マネタイズは任意の寄付（チップ）だけ（§9）。
5. **クレジットを必ず表示**。CMSL のクレジットを「この曲について」画面と「情報」画面に表示する。
6. **サーバーに負担をかけない**。CMSL のサイトを、アプリから直接スクレイピングしない。カタログは事前生成した静的 JSON を配信し、アプリは mp3 の再生時だけ CMSL のサーバー（`classical-sound.up.seesaa.net`）にアクセスする。

### 1.3 音源の利用条件（CMSL サイトの記載に基づく）
- ダウンロード用 mp3（「🎵こちら」ボタンなど `.mp3` リンク）はフリー素材。商用利用・加工が可能で、使用許諾も連絡も不要。
- 著作権は制作者に帰属する（放棄されていない）。表示ライセンスは Creative Commons 表示 2.1 日本。
- **ストリーミング専用のファイルはライセンス対象外**なので収録しない。
- 再配布の可否は明記されていない。アプリはファイルを再ホストせず、CMSL の URL から直接再生する。
- ストア審査に備えて、運営者から**書面（メール）で許諾を得る**（§10.2）。

## 2. システム構成

```
┌────────────────────────┐   月1回 + 手動実行
│ GitHub Actions          │──────────────┐
│  catalog/build_catalog  │  巡回 (1.5s間隔) ▼
└──────────┬─────────────┘   classical-sound.seesaa.net（HTML）
           │ catalog.json / manifest.json を生成・検証
           ▼
┌────────────────────────┐
│ 静的ホスティング          │  GitHub Pages（または Cloudflare Pages）
│  /v1/manifest.json      │
│  /v1/catalog.json       │
└──────────┬─────────────┘
           │ HTTPS GET（ETag / If-None-Match）
           ▼
┌────────────────┐  ┌────────────────┐
│ iOS アプリ       │  │ Android アプリ  │  ── 再生時のみ ──▶ classical-sound.up.seesaa.net/*.mp3
│ SwiftUI+AVPlayer│  │ Compose+Media3 │
└────────────────┘  └────────────────┘
```

- 配信先は **GitHub Pages**（`https://kate941-su.github.io/classicplayer/v1/`）に決定（2026-11-20、オーナー）。アプリはこのベース URL を定数で持つ。
- サーバー側のロジックは持たない（静的ファイルのみ）。検索・絞り込みはすべてアプリ内で行う。
- アプリには**同梱カタログ（シード）**を入れる。初回起動やオフライン時もカタログを閲覧できる。

## 3. カタログ

### 3.1 生成パイプライン（`catalog/`）
- `build_catalog.py`（既存）: サイトを巡回し、`catalog.json` と `catalog.report.json` を出力する。
- 追加実装:
  - `overrides.json`: 手動補正ファイル。タイトル解析の失敗、ジャンル名の整形、作曲家名の統一、除外する記事を記述する（§3.4）。
  - `genre_map.json`: CMSL のカテゴリ名をアプリの表示ジャンルに対応づける（§3.3）。
  - `validate_catalog.py`: `schema/catalog.schema.json` で検証し、整合性をチェックする（ID 重複、参照切れ、URL 形式）。
  - `make_manifest.py`: `manifest.json` を生成する（バージョン、SHA-256、件数、生成日時）。
- 実行: GitHub Actions（`.github/workflows/catalog.yml`）で毎月1日と手動トリガー時に実行する。HTML キャッシュは Actions の cache に保存し、2回目以降は差分取得（新しい記事だけ）にする。
- 安全弁: 前回より曲数が 10% 以上減ったら公開を止め、Issue を立てる（サイト構造の変化を検知するため）。

### 3.2 スキーマ（schemaVersion 1）
正式な定義は `schema/catalog.schema.json`。要点:

```jsonc
{
  "schemaVersion": 1,
  "generatedAt": "2026-12-01T03:00:00+00:00",
  "source": "https://classical-sound.seesaa.net/",
  "license": { "name": "...", "credit": "CMSL クラシック名曲サウンドライブラリー", "url": "...", "notes": "..." },
  "genres":    [{ "id": "piano", "name": "ピアノ", "nameEn": "Piano", "order": 10, "trackCount": 120 }],
  "composers": [{ "id": "l-v-beethoven", "name": "ベートーヴェン", "nameEn": "L.V.Beethoven", "trackCount": 42 }],
  "works":     [{ "id": "l-v-beethoven--...", "title": "ピアノソナタ 第8番 ハ短調 Op.13 「悲愴」", "composerId": "...", "genreId": "..." }],
  "tracks": [{
    "id": "474143449",                 // 記事ID（1記事に複数mp3があれば "474143449-0" 形式）。恒久的に変えない
    "title": "ベートーヴェン：ピアノソナタ 第8番 ... 第2楽章 [2020][AR]",
    "titleEn": "L.V.Beethoven:Piano Sonata No.8 ...",
    "composerId": "l-v-beethoven",
    "workId": "l-v-beethoven--...",
    "genreId": "piano",
    "movement": "第2楽章",             // null可
    "tags": ["2020", "AR"],
    "audioUrl": "https://classical-sound.up.seesaa.net/image/....mp3",
    "fileName": "....mp3",
    "articleUrl": "https://classical-sound.seesaa.net/article/474143449.html",
    "publishedAt": "2020-03-20T18:18:00+09:00",   // null可
    "durationSec": null                             // 将来拡張。現状は null
  }]
}
```

**契約のルール**（`schema/catalog.schema.json` で検査する）:
- 生成側はスキーマにあるキーを**すべて出力**する（値がないときは省略せず `null`。`tags` は空配列）。スキーマにないキーは出力しない（`additionalProperties: false`）。
- アプリのデコーダーは**未知のキーを無視**する（任意フィールドの追加は `schemaVersion` を上げずに行えるようにするため）。
- URL は `audioUrl` が `https://classical-sound.up.seesaa.net/〜.mp3`、`articleUrl` が `https://classical-sound.seesaa.net/article/{数字}.html` に限る。日時は RFC 3339（タイムゾーン付き）。
- ID の重複と参照切れ（`composerId` / `workId` / `genreId`）はスキーマでは表せないので、`validate_catalog.py` で検査する（PLAN 0.5）。

**ID の安定性**: `track.id` はお気に入りや再生履歴のキーになるため、生成し直しても変えてはならない。記事ID（Seesaa の `/article/{id}.html`）を元にする。`composer.id` と `work.id` は slug なので、表記揺れの修正で変わることがある。アプリはこれらを永続化しない（永続化するのは `track.id` だけ）。

### 3.3 ジャンル
CMSL のカテゴリをそのまま使うと、名前が長いものや細かすぎるものが出る。`genre_map.json` で次の表示ジャンルにまとめる（初版の案。実際のカテゴリ一覧を見て確定する）。

| 表示ジャンル | nameEn | 例（CMSL カテゴリ） |
|---|---|---|
| 交響曲 | Symphonies | 交響曲 |
| 管弦楽曲 | Orchestral | 管弦楽曲、序曲 |
| 協奏曲 | Concertos | 協奏曲 |
| ピアノ | Piano | 器楽曲・Piano |
| 器楽・室内楽 | Chamber & Instrumental | 室内楽、器楽曲（ピアノ以外） |
| 声楽・オペラ | Vocal & Opera | 歌劇、声楽曲、合唱 |
| バロック | Baroque | （時代でまとめたカテゴリがある場合） |
| その他 | Other | 上記に当てはまらないもの |

`order` で表示順を指定する。マップにないカテゴリは「その他」に入れ、`catalog.report.json` の警告に載せる。

### 3.4 overrides.json
```jsonc
{
  "exclude": ["500000002"],                       // 記事IDで除外
  "tracks": { "474143449": { "composer": "ベートーヴェン", "work": "...", "movement": "第2楽章" } },
  "composerAliases": { "L.v.ベートーヴェン": "ベートーヴェン", "ベートーベン": "ベートーヴェン" },
  "composerEn": { "ベートーヴェン": "Ludwig van Beethoven" }
}
```

### 3.5 manifest.json
```json
{ "schemaVersion": 1, "catalogVersion": "2026.12.01", "catalogUrl": "catalog.json",
  "sha256": "…", "trackCount": 812, "generatedAt": "…", "minAppSchema": 1 }
```
正式な定義は `schema/manifest.schema.json`。`sha256` は catalog.json のバイト列のハッシュ。`catalogVersion` は `generatedAt`（UTC）の日付で、中身（sha256）が前回と同じなら前回の値を引き継ぎ、同じ日に出し直すときは `YYYY.MM.DD.2` のように連番を付ける（`make_manifest.py`）。
アプリは manifest を先に取得し、`catalogVersion` が変わったときだけ catalog を取得する。`schemaVersion` がアプリの対応範囲外なら、更新せず手持ちのカタログを使い続ける。

## 4. 画面仕様

### 4.1 画面構成
```
タブ: [ホーム] [検索] [ライブラリ] [情報]
                 └ 下部にミニプレイヤーを常時表示（再生中のみ）→ タップでフルプレイヤー
ホーム ─ ジャンル一覧 ─ ジャンル詳細（作曲家一覧）─ 作曲家詳細（作品一覧）─ 作品詳細（楽章・トラック一覧）
```

### 4.2 ホーム
- 上部: 「新着」横スクロール（`publishedAt` が新しい順に10件）。
- 本体: ジャンルのカードグリッド（2列。名前と曲数を表示）。並びは `order` 順。
- 「おまかせ再生」ボタン: 全曲（または選択中のジャンル）からシャッフル再生する。

### 4.3 ジャンル詳細
- 作曲家の一覧（曲数の多い順。「名前順」に切り替え可能）。
- 右上に「このジャンルをシャッフル再生」ボタン。

### 4.4 作曲家詳細
- 作品の一覧（各作品の楽章数を表示）。作品が1つで1トラックだけのものは、トラック行として直接表示する。
- 「すべて再生」ボタン（作品順、楽章順）。

### 4.5 作品詳細
- トラック（楽章）の一覧。並びは楽章番号順（`movement` の数値を抽出。なければ `publishedAt`）。
- 行: 楽章名、タグ（例「2020」「AR」）、お気に入りの☆。
- 「作品を通して再生」ボタン。1行をタップすると、その曲から作品の最後までをキューに入れる。
- 行の「…」メニュー: お気に入り、次に再生、キューに追加、この曲について（原典記事へのリンクとクレジット）。

### 4.6 検索
- 対象: 曲タイトル（日本語・英語）、作曲家名（日本語・英語）、作品名。端末内のカタログだけを検索する（ネットワーク不要）。
- 正規化: 全角と半角、ひらがなとカタカナ、長音・中黒・空白、大文字と小文字、「ヴ/ブ」「ヴェ/ベ」の揺れを吸収する（例「ベートーベン」→ベートーヴェン、「beethoven」）。
- 結果は「作曲家」「作品」「曲」のセクションに分けて表示する。入力のたびにインクリメンタルに更新する（150ms のデバウンス）。
- 未入力時は「最近の検索」（端末内に最大10件）とジャンルのチップを表示する。

### 4.7 ライブラリ
- お気に入り（曲）。並び替えは追加日順、作曲家順。
- 最近再生した曲（最大100件）。
- ※ プレイリスト機能は v1.1 以降（§11）。

### 4.8 フルプレイヤー
- 表示: 作品名、楽章、作曲家、ジャンルの色に合わせた生成アートワーク（§4.10）。
- 操作: 再生/一時停止、前/次、シークバー（経過時間と残り時間）、シャッフル、リピート（オフ/全体/1曲）、お気に入り、キュー表示、共有（原典記事の URL）。
- 「この曲について」: 原典記事へのリンクとクレジットを表示する。

### 4.9 情報
- アプリについて、**CMSL クレジット（ロゴではなくテキストとリンク）**、利用条件の要約、プライバシーポリシー（「データを収集しません」）、オープンソースライセンス一覧、お問い合わせ、カタログの版と更新日、手動更新ボタン。
- 「開発を応援する」（寄付。§9）。

### 4.10 アートワーク
CMSL の音源には画像がないため、**アプリ内で生成する抽象アートワーク**を使う。作曲家 ID のハッシュから色相を決め、ジャンルごとに図形パターンを変える（例: ピアノは鍵盤の縞、交響曲は同心円）。外部の画像や肖像写真は使わない。

### 4.11 デザイン
- トーンは落ち着いた「コンサートホール」。ライトとダークに対応（システム設定に従う）。
- 日本語を主とし、英語ローカライズも用意する（端末の言語設定に従う）。英語 UI では `nameEn` / `titleEn` を優先して表示し、ない場合は日本語にフォールバックする。
- アクセシビリティ: Dynamic Type / フォントスケールに対応。VoiceOver / TalkBack 用のラベルを付ける。タップ領域は 44pt / 48dp 以上。コントラストは WCAG AA。

## 5. 再生仕様

| 項目 | 仕様 |
|---|---|
| 方式 | `audioUrl` を HTTPS で直接ストリーミングする（プログレッシブ再生） |
| バックグラウンド再生 | 対応（iOS: Audio Background Mode / Android: MediaSessionService） |
| ロック画面・通知 | タイトル、作曲家、アートワーク、再生/一時停止、前/次、シーク |
| 割り込み | 電話やほかのアプリの再生で一時停止し、割り込みが終わったら再開する（OS の推奨に従う） |
| イヤホンを外したとき | 一時停止する |
| ギャップレス | 同じ作品の連続した楽章は、次の曲を先読みして途切れを最小にする（iOS: AVQueuePlayer / Android: Media3 のプレイリスト） |
| キュー | 「作品を通して」「ジャンルのシャッフル」「お気に入り」などのコンテキストからキューを作る。並べ替えと削除ができる |
| 状態の復元 | アプリを再起動したら、最後のキューと位置を復元する（自動では再生しない） |
| エラー | 404 やネットワークエラーの曲はスキップし、トーストで知らせる。3曲続けて失敗したら停止する |
| キャッシュ | OS / プレイヤー標準の HTTP キャッシュ（最大 200MB）。**明示的なダウンロード保存は v1.0 では提供しない**（§10.2 の許諾を得てから v1.1 で検討する） |
| 音量 | 端末の音量に従う。アプリ独自のノーマライズはしない |

## 6. データ保存（端末内）

| データ | iOS | Android |
|---|---|---|
| カタログ（最新版） | Application Support/catalog.json | filesDir/catalog.json |
| 同梱シード | Bundle resource | assets/catalog.json |
| お気に入り（track.id と追加日時） | SwiftData | Room |
| 再生履歴（track.id と日時、最大100件） | SwiftData | Room |
| 最近の検索 | UserDefaults | DataStore |
| 再生キューと位置 | UserDefaults（JSON） | DataStore |

カタログを更新して `track.id` が消えた場合、そのお気に入りは「この曲は現在利用できません」としてグレー表示する（削除はしない）。

## 7. カタログ取得と更新

1. 起動時、ローカルカタログ（なければシード）を即座に読み込んで表示する。ネットワークの完了を待たない。
2. バックグラウンドで `manifest.json` を取得する（ETag を使用。前回の確認から24時間以内ならスキップ）。
3. `catalogVersion` が新しければ `catalog.json` を取得し、SHA-256 とスキーマを検証してから差し替える。失敗したら旧版を維持する。
4. 「情報」画面の手動更新ボタンでは、24時間の制限を無視して確認する。

## 8. 技術スタック

### 8.1 iOS
- iOS 17.0 以上、Swift 6、SwiftUI、Observation（`@Observable`）、SwiftData。
- 再生: AVFoundation（`AVQueuePlayer`）、`MPNowPlayingInfoCenter`、`MPRemoteCommandCenter`、`AVAudioSession`（`.playback`）。
- 課金: StoreKit 2（消耗型のチップ）。
- 依存ライブラリ: **原則ゼロ**（Swift Package を使う場合は MIT/Apache のものだけ）。
- テスト: XCTest または Swift Testing（カタログのデコード、検索の正規化、キュー生成、ViewModel）。UI テストは主要フローを1本。
- **ビルドには macOS と Xcode 16 以上が必要**（Linux 環境の Claude Code では iOS のビルドとテストを実行できない）。

### 8.2 Android
- minSdk 26 / targetSdk は最新の安定版。Kotlin、Jetpack Compose（Material 3）、Navigation Compose。
- 再生: AndroidX Media3（ExoPlayer、MediaSessionService、MediaController）。
- データ: Room、DataStore、kotlinx.serialization、OkHttp（ETag キャッシュ）。
- DI: Hilt（または手動 DI。シンプルさを優先して選ぶ）。
- 課金: Google Play Billing Library（消耗型のチップ）。
- テスト: JUnit + Turbine（Flow）、Robolectric（必要な部分のみ）、Compose UI テストは主要フローを1本。
- ビルド: `./gradlew assembleDebug test lint` が Linux で通ること。

### 8.3 共通
- `schema/catalog.schema.json` と `fixtures/catalog.sample.json`（20曲程度）を両プラットフォームのテストで共有する。
- 検索の正規化ルールは `docs/search-normalization.md` に表で定義し、両方の実装で同じテストケース（`fixtures/search_cases.json`）を通す。

## 9. マネタイズ（寄付・チップ）

- 形式: **消耗型のアプリ内課金による「チップ」**を3段階（例 ¥160 / ¥480 / ¥1,200。価格帯は各ストアのティアから選ぶ）。
- 何もアンロックしない（純粋な応援）。購入後に「ありがとうございます」画面を表示し、端末内に「応援者」バッジのフラグを立てる（表示のみで、機能差はない）。
- 外部の寄付リンク（Ko-fi、PayPal など）は**アプリ内に置かない**（ストアの規約違反になるため）。
- 「復元」は不要（消耗型のため）。ただし応援者バッジは端末内のフラグなので、再インストールで消える旨を表示する。
- 寄付を促す表示は「情報」タブと、累計再生が50曲に達したときの1回だけの控えめなカード。**再生の途中や起動時にポップアップは出さない**。
- CMSL への還元方針（収益の一部を還元するか、などの扱い）は、オーナーが運営者と相談して決める。決まったら、寄付画面の説明文に反映する。

## 10. リリース要件

### 10.1 ストア
- アプリ名（案）: 「クラシック名曲プレイヤー – CMSL」など。CMSL の名前を使う場合は、運営者の了承を得る。
- プライバシー: iOS の App Privacy は「データ収集なし」、Google Play のデータセーフティは「収集なし・共有なし」。
- 必須リンク: サポート URL、プライバシーポリシー（GitHub Pages 上に置く）。
- 年齢レーティング: 全年齢。

### 10.2 権利関係（審査対策）

## 11. スコープ

### v1.0（MVP）
カタログ閲覧（ジャンル → 作曲家 → 作品 → 楽章）、検索、再生（バックグラウンド、ロック画面、キュー、シャッフル、リピート）、お気に入り、履歴、カタログ自動更新、情報とクレジット、ライト/ダーク、日本語と英語、チップ。

プレイリスト、スリープタイマー、CarPlay / Android Auto、オフライン保存（許諾を得てから）、ウィジェット、iPad と大画面向けのレイアウト、作品の解説文（CMSL 記事からの抜粋は**しない**。リンクのみ）。

### やらないこと
広告、アカウント、SNS 機能、クラシック以外の音源、CMSL 以外のソースの混在、ユーザー追跡。

## 12. 受け入れ基準（v1.0 全体）
- [ ] 実カタログの全トラックが、ジャンル → 作曲家 → 作品 → 楽章でたどれる（「その他」と「作曲者不明」は全体の5%以下）
