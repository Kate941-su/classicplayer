# 検索の正規化（SPEC §4.6）

iOS と Android は同じ規則で正規化し、同じテストケース（`fixtures/search_cases.json`）を通す。

## 正規化（検索語と、検索対象の文字列の両方にかける）

上から順に適用する。

| # | 処理 | 例 |
|---|---|---|
| 1 | Unicode NFKC（全角英数 → 半角、半角カナ → 全角カナ、濁点の合成） | `ＢＥＥＴＨＯＶＥＮ` → `BEETHOVEN`、`ﾍﾞｰﾄｰｳﾞｪﾝ` → `ベートーヴェン` |
| 2 | 小文字にする（ロケールに依存しない変換） | `BEETHOVEN` → `beethoven` |
| 3 | ラテン文字の発音記号を外す（NFD → U+0300〜U+036F を削除 → NFC）。日本語の濁点（U+3099/309A）は対象外 | `dvořák` → `dvorak` |
| 4 | ひらがな（U+3041〜U+3096）をカタカナにする（+0x60） | `べーとーゔぇん` → `ベートーヴェン` |
| 5 | 「ヴ」の揺れをそろえる: `ヴァ→バ` `ヴィ→ビ` `ヴェ→ベ` `ヴォ→ボ` `ヴュ→ビュ` `ヴ→ブ`（この順） | `ベートーヴェン` → `ベートーベン` |
| 6 | 次の文字を削除する: 空白類（全角空白を含む）、長音 `ー`、中黒 `・`、記号 `` - ‐ – — _ . , ' " / : ; ! ? ( ) [ ] { } 「 」 『 』 【 】 、 。 〜 ~ `` | `ベートーベン` → `ベトベン`、`L.V.Beethoven` → `lvbeethoven` |

## 照合

- 検索語は**正規化の前に**空白類（全角空白を含む）で語に分け、それぞれを正規化する。正規化して空になった語は捨てる。語が 0 個なら結果は空
- すべての語が、対象のキーのどれかに**部分一致**したらヒット（AND）
- 対象とキー

| セクション | キー（★は主キー） |
|---|---|
| 作曲家 | ★`name`、★`nameEn` |
| 作品 | ★`title`、作曲家の `name`・`nameEn` |
| 曲 | ★`title`、★`titleEn`、作品の `title`、作曲家の `name`・`nameEn` |

## 並び順（各セクションの中）

1. すべての語が主キーの**先頭**に一致するもの
2. すべての語が主キーのどれかに一致するもの
3. それ以外（作曲家名などの副キーで一致したもの）

同じ順位の中では、作曲家は曲数の多い順 → 名前順、作品はタイトル順、曲は作品の順（タイトル順）→ 楽章順。表示する件数の上限は作曲家 20、作品 50、曲 100。

テストケースの `expect` は「含むべき ID」で、上限や並び順の細部はプラットフォームの実装に任せる。`first` があるときは、そのセクションの先頭がその ID であることを確かめる。
